# Посещаемость

Мобильное PWA для учёта посещаемости учебной группы. Отметки по датам и парам, классный час, календарь, месячная ведомость в «бумажном» стиле, CSV для Excel, печать/PDF и резервные копии. Все данные хранятся только в браузере на телефоне или компьютере — регистрация и сервер не нужны. В приложении шесть тем оформления и плавные переходы, которые раскрывают новый экран кругом из точки нажатия.

В публичной демонстрационной версии уже создана группа **«Моя группа»** с вымышленными студентами — этого достаточно, чтобы посмотреть отметки, отчёты и остальные возможности. Личная версия для телефона содержит реальный список студентов; их ФИО в публичный репозиторий не попадают.

## Возможности

- **Отметка по одному студенту** за выбранную дату и занятие (пары 1–8 и классный час). Пять статусов: «Есть», «Не было», «Болеет», «Уважительная причина», «Опоздал».
- **Опоздание**: можно указать, на какое занятие студент пришёл, и добавить комментарий.
- **Автосохранение** после каждого ответа и автоматический переход к следующему студенту.
- **Пропустить / Назад**, продолжение с первого неотмеченного, запуск заново с очисткой отметок выбранного занятия.
- **«Отметить всех присутствующими»** для быстрой отметки группы.
- **Продолжение состава**: перенос отметок с предыдущего занятия — все, кто был, остаются, а вы отмечаете только ушедших и пришедших.
- **Несколько пар в один день**: у каждой пары свой набор отметок.
- **Классный час** по понедельникам («Разговоры о важном») и четвергам («Россия — мои горизонты») как отдельное занятие; его можно добавить в любой день, изменить время или удалить.
- **Дневной отчёт**: сколько занятий посетил каждый студент за выбранный день.
- **Редактирование прошлых отметок** из итогов, календаря, карточки дня или ячейки отчёта.
- **Календарь** с днями, где есть отметки, и детализацией по занятиям.
- **Студенты и группы**: поиск, ручной порядок, сортировка по алфавиту, добавление, переименование, архив и удаление. Добавлять и удалять студентов можно прямо в разделе «Студенты», а из карточки группы открывается её список. Удалённые в архив студенты сохраняют историю.
- **Шесть тем оформления** в настройках: светлая, тёмная, «Океан», «Лес», «Закат», «Ягода». Тема применяется сразу и сохраняется.
- **Плавные переходы**: новый экран раскрывается кругом из точки нажатия; при включённом уменьшении движения анимация отключается.
- **Нижнее меню со свайпом**: горизонтальный свайп по вкладкам «листает» разделы, короткий флик открывает соседнюю вкладку, а удержание показывает «жидкий стеклянный» курсор; обычное нажатие тоже работает.
- **Обновления APK по воздуху (OTA)**: приложение проверяет `update.json`, скачивает новую версию, сверяет SHA-256, имя пакета, `versionCode` и подпись, затем открывает системный установщик. Автопроверка при запуске выполняется не чаще одного раза в 6 часов.
- **Напоминания**: несколько времён, выбор дней недели, системные уведомления; в APK приходят даже при закрытом приложении, в браузере — пока вкладка открыта.
- **Месячный отчёт**: символы `+`, `Н`, `Б`, `У`, `О`, построчные и групповые итоги, формула `(Есть + Опоздал) / Всего отмечено × 100`, CSV и печать.
- **Быстрая отправка отчёта с главной**: «За сегодня» или «За месяц» — CSV-файл сразу открывается в системном диалоге «Поделиться» (в браузере — Web Share API или скачивание).
- **Настройки**: расписание звонков отдельно для каждого дня недели (1–8 пар и классный час), резервная копия JSON, импорт, полная очистка с двойным подтверждением, инструкция по установке.
- **Офлайн-работа** после первого открытия: service worker кэширует оболочку и ресурсы сборки.

## Запуск

Нужен Node.js **20.19+** (или 22.12+) и npm.

```bash
npm install
npm run dev
```

Vite покажет адрес вида `http://localhost:5173/`. Откройте его в браузере. Для проверки с телефона в той же сети используйте `npm run dev -- --host` и адрес компьютера.

Сборка и локальный предпросмотр production-версии:

```bash
npm run build
npm run preview
```

Готовая сборка лежит в `dist/`.

> Service worker и офлайн-режим включены только в production-сборке (`npm run build` + `npm run preview` или размещение на хостинге). В режиме `npm run dev` они не регистрируются, чтобы не мешать разработке.

## Размещение в интернете

Приложение — статический сайт. Маршрутизация сделана через состояние, без URL-адресов, поэтому дополнительные rewrite-правила не нужны. В `vite.config.ts` уже стоит `base: './'` — сборку можно класть как в корень домена, так и в подпапку.

1. Загрузите проект в Git-репозиторий или перетащите папку на Netlify Drop.
2. Build command: `npm run build`.
3. Publish directory: `dist`.

### Vercel

1. Импортируйте репозиторий.
2. Framework preset: **Vite**.
3. Build command: `npm run build`, Output directory: `dist`.

### GitHub Pages

1. Соберите проект: `npm run build`.
2. Опубликуйте содержимое `dist/` в ветке `gh-pages` (например, через `gh-pages` или GitHub Actions).

Скопируйте файлы из `dist/` на сервер. Нужен HTTPS — без него не работают установка PWA и уведомления (исключение — `localhost`).

## Установка на телефон

### Готовый APK для Android

В корне проекта лежит собранный файл **`Attendance.apk`** (около 0,2 МБ). Это автономная Android-обёртка: интерфейс, стили и все данные уже внутри APK, интернет не требуется.

1. Передайте `Attendance.apk` на телефон (USB, облако или мессенджер).
2. Откройте файл в «Проводнике» / «Загрузках».
3. Разрешите установку из этого источника, если система спросит.
4. На Xiaomi/Redmi дополнительно включите **Настройки → Расширенные настройки → Для разработчиков → Установка через USB**, если установка блокируется.

Что работает в APK:

- полностью офлайн, без сервера и регистрации;
- системные уведомления Android, в том числе когда приложение закрыто (через системные будильники AlarmManager);
- сохранение CSV и JSON в папку **«Загрузки»**;
- отправка CSV-отчёта в любое приложение через системный диалог **«Поделиться»** (мессенджер, почта, диск);
- системный диалог печати Android, A4 альбомная, отчёт помещается на одну страницу;
- выбор JSON-файла для импорта через системный проводник.

Данные APK хранятся в локальном хранилище WebView и удаляются при удалении приложения. Перед переустановкой или сменой телефона сделайте **Экспорт JSON**.

Пересборка APK:

```powershell
npm run build
powershell -ExecutionPolicy Bypass -File .\android\build-apk.ps1
```

Для отладочной сборки с включённой отладкой WebView добавьте `-DebugBuild`. Нужны JDK 17 и Android SDK с build-tools 35; пути к ним заданы в начале `android/build-apk.ps1`. APK подписывается локальным ключом `android/keystore/attendance.jks` (alias и пароль `attendance`); сохраните его, чтобы обновлять приложение поверх установленного.

### Обновления APK по воздуху (OTA)

В APK версии 1.4.0 появился встроенный загрузчик обновлений. Он не заменяет приложение через браузер, а скачивает новый APK и передаёт его системному установщику Android.

Как это работает:

1. В **Настройках → Обновления приложения** укажите адрес `update.json` и при необходимости включите **«Проверять при запуске»**.
2. Приложение сравнивает `versionCode` из манифеста с установленным. Если доступна новая версия, показывает заметки и кнопку загрузки.
3. APK скачивается во внутренний кэш, проверяются:
   - имя пакета `ru.netla.attendance`;
   - `versionCode` совпадает с указанным в `update.json`;
   - SHA-256 файла;
   - подпись APK совпадает с подписью установленного приложения.
4. Только после всех проверок открывается системный установщик. Android может попросить разрешение **«Установка неизвестных приложений»**; его нужно выдать один раз для «Посещаемости».
5. Группы, студенты, отметки и настройки при обновлении сохраняются.

Формат `release/update.json`:

```json
{
  "versionName": "1.4.7",
  "versionCode": 12,
  "apkUrl": "Attendance-1.4.7.apk",
  "sha256": "…",
  "size": 247000,
  "notes": "Что изменилось",
  "publishedAt": "2026-11-07"
}
```

`apkUrl` может быть относительным — тогда файл ищется рядом с `update.json`. Сборка `build-apk.ps1` сама копирует APK в `release/`, считает SHA-256, создаёт `release/update.json` и дублирует текущий релиз в `docs/` для GitHub Pages.

Локальный сервер для проверки OTA:

```bash
npm run update-server
```

Сервер раздаёт папку `release/` на `http://127.0.0.1:8787/`. Для телефона, подключённого по USB, можно выполнить `adb reverse tcp:8787 tcp:8787` и указать в настройках приложения `http://127.0.0.1:8787/update.json`. Для интернета разместите содержимое `release/` на HTTPS-хостинге и укажите его адрес.

Публичная демо-версия размещена на GitHub Pages:

```text
https://netlapps.github.io/attendance-app/update.json
```

Страница загрузки APK: `https://netlapps.github.io/attendance-app/`. Живое веб-демо (PWA, те же вымышленные студенты): `https://netlapps.github.io/attendance-app/app/`. Адрес `https://netlapps.github.io/attendance-app/update.json` уже указан по умолчанию в новых установках; его можно изменить в **Настройках → Обновления приложения**. Старый локальный адрес `http://127.0.0.1:8787/update.json` автоматически заменяется на публичный. Провод и локальный сервер не нужны: телефон скачивает APK по HTTPS. В публичной сборке — вымышленные студенты; при обновлении существующие группы, студенты и история на телефоне сохраняются.

Важно:

- для интернета используйте только HTTPS; HTTP разрешён для локальной сети и тестов;
- обновление устанавливается только поверх приложения с той же подписью — ключ `android/keystore/attendance.jks` хранится только локально и в репозиторий не публикуется; не теряйте его;
- Play Protect может предупредить о самоподписанном APK. Если установка заблокирована, выберите **«Установить без проверки»** или временно отключите сканирование Play Protect; после проверки его лучше включить обратно;
- если установка отменена или заблокирована, текущая версия и все данные остаются на месте.

## Как пользоваться

1. На главной нажмите **«Отметить посещаемость»**.
2. Выберите дату и пару. По умолчанию подставляется текущая дата и текущая пара по расписанию.
3. Отмечайте студентов по одному. После ответа приложение само переходит дальше.
4. «Пропустить» оставляет студента без отметки, «Назад» возвращает к предыдущему.
5. В любой момент откройте **«Итоги»**, чтобы проверить и исправить отметки.
6. Для второй пары в тот же день нажмите **«Отметить ещё одну пару»** на экране итогов.
7. Если группа осталась на следующую пару, на экране настройки нажмите **«Продолжить с N пары»**: статусы перенесутся, и останется отметить только ушедших и пришедших.

Если вернуться к уже начатой паре, приложение предложит продолжить с первого неотмеченного студента или начать заново. «Начать заново» удаляет отметки только выбранной пары за выбранную дату.

### Несколько пар подряд

Обычно студенты, пришедшие на первую пару, остаются и на следующие. Для этого на экране настройки пары (2-й и далее) появляется кнопка **«Продолжить с N пары»**:

- все, кто был на предыдущей паре, получают тот же статус;
- «Опоздал» на следующей паре становится «Есть» — студент уже на месте;
- уже существующие отметки текущей пары не перезаписываются;
- после переноса открывается список студентов: нажмите на ушедшего и выберите **«Не было»**, а на пришедшего — **«Есть»** или **«Опоздал»**.

Перенос доступен и на экране пошаговой отметки, если пара открыта напрямую из календаря.

### Классный час

Классный час хранится как отдельное занятие, поэтому у него свои отметки, итоги и колонка в отчёте. По умолчанию:

- понедельник — «Разговоры о важном», 08:30–09:00;
- четверг — «Россия — мои горизонты», 08:15–09:00.

На экране отметки классный час показывается первым, перед первой парой. С него можно перенести состав на первую пару той же кнопкой **«Продолжить с классного часа»**. В настройках расписания классный час можно добавить в любой день, изменить время или удалить; после удаления он не появляется снова.

### Дневной отчёт

В календаре откройте нужный день — под списком занятий появится раздел **«Посещаемость за день»**. Для каждого студента показано, сколько занятий он посетил, например `3 из 4`, и номера этих занятий. «Есть» и «Опоздал» считаются посещением; у студентов, не посетивших ни одного занятия, будет `0 из N`.

### Статусы

| Статус | Символ в отчёте | Что означает |
| --- | --- | --- |
| Есть | `+` | Студент присутствовал |
| Не было | `Н` | Отсутствовал |
| Болеет | `Б` | Отсутствовал по болезни |
| Уважительная причина | `У` | Отсутствовал по уважительной причине |
| Опоздал | `О` | Присутствовал, но опоздал |

Для «Опоздал» можно выбрать пару, на которую студент пришёл, и оставить комментарий.

### Темы и переходы

В **Настройках → Тема оформления** доступны шесть тем: светлая, тёмная, «Океан», «Лес», «Закат» и «Ягода». Выбранная тема применяется сразу, сохраняется в данных приложения и восстанавливается при следующем запуске без мигания светлого фона.

Переход между экранами сделан через View Transitions API: новый экран раскрывается кругом из точки последнего нажатия. Если браузер не поддерживает этот API или в системе включено уменьшение движения, экран меняется без анимации. Печать и отчёты при этом не затрагиваются.

### Студенты и группы

- **Студенты** — поиск по ФИО, изменение имени, ручное перемещение стрелками, сортировка по алфавиту, добавление и удаление.
- **Удалить навсегда** — красная кнопка с корзиной прямо в активном списке или в архиве; вместе со студентом удаляется его история. Приложение предупреждает об этом.
- **Архив** — студент исчезает из списка отметок, но его прошлые отметки остаются в отчётах.
- **Группы** — создание, переименование, куратор, переключение и удаление. На карточке группы есть кнопка **«Студенты группы»**, которая сразу открывает её список. При удалении группы удаляются её студенты и вся история посещаемости.
- Кнопка **«Моя группа»** на главной открывает список групп.

### Расписание звонков

В **Настройках** расписание задаётся отдельно для каждого дня недели: выберите **Пн–Вс** и отредактируйте начало и конец пар (до 8 пар в день), а также классный час. Кнопки **«Добавить пару»** и **«Сбросить день»** помогают быстро настроить день. Время показывается на экранах отметки и итогов, а также используется для подсказки текущей пары.

Стартовое расписание заполнено по фото:

| День | Классный час | 1 пара | 2 пара | 3 пара | 4 пара | 5 пара |
| --- | --- | --- | --- | --- | --- | --- |
| Пн | 08:30–09:00 «Разговоры о важном» | 09:10–10:30 | 10:40–12:00 | 12:40–14:00 | 14:10–15:30 | 15:40–17:00 |
| Вт, Ср, Пт | — | 08:15–09:35 | 09:45–11:05 | 12:00–13:20 | 13:30–14:50 | 15:00–16:20 |
| Чт | 08:15–09:00 «Россия — мои горизонты» | 09:10–10:30 | 10:40–12:00 | 12:40–14:00 | 14:10–15:30 | 15:40–17:00 |
| Сб | — | 08:15–09:35 | 09:45–11:05 | 11:15–12:35 | 12:45–14:05 | — |
| Вс | — | пар нет | | | | |

Линейка в понедельник (08:15–08:30) в расписании не учитывается — отмечается только классный час и пары.

### Отчёт, CSV и печать

Отчёт строится за выбранный месяц и группу. В таблицу попадают только те даты и пары, по которым есть хотя бы одна отметка. Для каждого студента считаются:

- «Всего отмечено» — количество записей;
- «Есть», «Не было», «Болеет», «Уважительная», «Опоздал»;
- `% посещаемости = (Есть + Опоздал) / Всего отмечено × 100`.

Внизу таблицы выводятся итоги по группе. Кнопка **«CSV для Excel»** скачивает файл с разделителем `;` и BOM UTF-8 — Excel корректно открывает кириллицу. Кнопка **«Печать / PDF»** открывает системный диалог печати; в печатной версии скрываются фильтры, добавляются шапка, сводка, легенда и формула. Рекомендуется **A4, альбомная ориентация**.

### Быстрая отправка отчёта с главной

На главном экране есть карточка **«Отправить отчёт»** с двумя кнопками:

- **«За сегодня»** — файл со всеми отмеченными парами текущей даты;
- **«За месяц»** — файл за месяц, который показан на главной (текущий месяц).

Файл формируется в том же «бумажном» формате, что и месячная ведомость: шапка с группой и периодом, строки студентов, символы `+`, `Н`, `Б`, `У`, `О`, итоги и процент посещаемости. Это обычный CSV с разделителем `;` и BOM UTF-8, поэтому он открывается в Excel, «Google Таблицах» и большинстве просмотрщиков.

В Android APK нажатие открывает системный диалог **«Поделиться»**: можно сразу отправить файл в Telegram, WhatsApp, почту, облако или сохранить в «Загрузки». В браузере используется Web Share API; если он недоступен, файл просто скачивается. Если за выбранный период ещё нет отметок, приложение показывает подсказку и не создаёт пустой файл.

### Резервные копии

**Настройки → Экспорт JSON** сохраняет все группы, студентов, отметки и настройки в файл. **Импорт JSON** полностью заменяет текущие данные данными из файла; перед заменой показывается подтверждение с количеством групп, студентов и отметок.

Делайте резервную копию перед очисткой данных, сменой телефона или переустановкой браузера. Импорт проверяет структуру файла и не принимает повреждённый JSON.

**Очистить все данные** удаляет группы, студентов, историю и настройки после двух подтверждений. После очистки остаётся одна пустая группа «Моя группа», чтобы приложением можно было пользоваться дальше.

## Напоминания: APK и браузер

### Android APK

В APK напоминания планируются системными будильниками Android (`AlarmManager`), поэтому работают без открытого приложения:

- при сохранении настроек и при каждом запуске приложение создаёт точные будильники на ближайшие выбранные дни и время;
- будильник срабатывает, даже если приложение свёрнуто или закрыто, и показывает системное уведомление высокого приоритета со звуком и вибрацией;
- после срабатывания будильник автоматически переносится на следующую неделю;
- после перезагрузки телефона, смены времени/часового пояса или обновления APK расписание восстанавливается;
- если система запрещает точные будильники, используется отложенный будильник — он может сработать с задержкой;
- **принудительная остановка** приложения через настройки Android отменяет будильники до следующего запуска — это ограничение самой системы;
- на Xiaomi/Redmi/HyperOS включите автозапуск и снимите ограничения батареи для приложения, иначе система может задерживать будильники.

В **Настройках → Напоминания → Надёжность напоминаний** видно состояние разрешений:

- уведомления (можно запросить повторно);
- точные будильники (кнопка открывает системный запрос);
- ограничения батареи (кнопка снимает ограничение или открывает список);
- автозапуск Xiaomi (открывается системный экран автозапуска);
- кнопки **«Проверить сейчас»** и **«Через 10 секунд»**. Второй вариант позволяет закрыть приложение и убедиться, что уведомление приходит из фона.

Тестовое уведомление использует отдельный канал `reminders_v2` с высоким приоритетом, звуком, вибрацией и показом на экране блокировки. Если уведомления не приходят, проверьте, что для приложения не отключён канал «Напоминания» в системных настройках.

### Браузер (PWA)

Без сервера и push-подписок браузер не даёт странице работать в фоне:

- пока вкладка открыта, приложение проверяет время каждые 20 секунд и показывает системное уведомление и баннер;
- если открыть приложение в течение **2 часов** после времени напоминания и за сегодня ещё нет отметок, появится догоняющий баннер;
- после полного закрытия вкладки уведомление не придёт. Для фоновых напоминаний установите APK.

Разрешение на уведомления запрашивается в **Настройках**. Если разрешение не выдано, приложение продолжает показывать баннер внутри вкладки и честно сообщает об ограничении.

## Резервное копирование и хранение данных

- Ключ данных: `attendance-app-data-v1` в `localStorage`.
- Ключ сработавших напоминаний: `attendance-app-fired-reminders-v1`.
- Данные не отправляются в интернет и не синхронизируются между устройствами.
- Очистка данных сайта в браузере, режим инкогнито и переустановка браузера могут удалить историю. Регулярно делайте JSON-бэкап.
- Объём `localStorage` обычно ограничен несколькими мегабайтами; для одной-двух групп с несколькими годами отметок этого достаточно, но стоит периодически проверять размер бэкапа.

- отчёт, проценты, CSV с BOM и `;`, печатные стили;
- студенты, архив, удаление, группы, массовое добавление;
- прямое добавление и удаление студента в разделе «Студенты», переход к списку из карточки группы;

- печать отчёта при включённой тёмной теме: заголовок, таблица и символы остаются светлыми и читаемыми;
- расписание, напоминания, импорт/экспорт, двойная очистка;
- фон напоминаний в APK: точный будильник AlarmManager сработал при закрытом приложении, системное уведомление появилось, следующее срабатывание перенесено на неделю;
- тёмная тема: статус-бар и панель навигации окрашиваются в фон темы, белых полос сверху и снизу нет;
- тёмная тема: пустые состояния, вторичный текст и кнопки читаются на тёмной поверхности; проверка контраста для отчётов, календаря, студентов и настроек;
- нижнее меню: свайп влево/вправо листает разделы, короткий флик открывает соседнюю вкладку, удержание показывает стеклянный курсор, обычные нажатия работают;
- OTA: проверка `update.json`, загрузка APK, проверка SHA-256 и подписи, открытие системного установщика, обновление 1.3.0 → 1.4.0 с сохранением списка студентов и тёмной темы;
- панель «Надёжность напоминаний»: статусы уведомлений, точных будильников и батареи, переходы в системные настройки, тест «сейчас» и «через 10 секунд» (проверено в Chromium с эмуляцией нативного моста);

- отсутствие горизонтальной прокрутки страницы, размеры кнопок, офлайн-перезагрузка после остановки сервера, манифест и иконки.

## Допущения

- В публичной версии — вымышленные студенты для демонстрации. Свой список можно добавить в разделе **Студенты** или импортировать из JSON. Реальные ФИО из личной ведомости в репозиторий не публикуются.
- По умолчанию создана одна группа «Моя группа». Куратор не указан.
- Расписание звонков заполнено по фото и отличается по дням недели: понедельник и четверг — 5 пар с 09:10, вторник/среда/пятница — 5 пар с 08:15, суббота — 4 пары с 08:15, воскресенье — без пар. Измените его в **Настройках** под своё учебное заведение.
- Классный час по умолчанию добавлен только в понедельник (08:30–09:00, «Разговоры о важном») и четверг (08:15–09:00, «Россия — мои горизонты»). В остальные дни его можно добавить вручную. Тема подставляется по дню недели автоматически, в расписании меняется только время.
- Линейка в понедельник (08:15–08:30) не моделируется: она не входит в посещаемость занятий.
- При обновлении со старой версии нетронутое типовое расписание (08:30–10:00 и далее) автоматически заменяется новым расписанием с фото; изменённое вручную старое расписание копируется на все дни недели, после чего его можно поправить по дням.
- Классный час добавляется при обновлении данных версии 1 → 2 один раз. Если после обновления удалить его в настройках, он не появится снова.
- Учебными днями по умолчанию считаются понедельник–суббота; воскресенье выключено в напоминаниях.
- Отчёт строится по календарному месяцу. Пустые клетки в таблице означают, что за этот день и пару отметки не было; они не считаются пропуском.
- Процент посещаемости считается только по фактически отмеченным записям, а не по числу всех возможных пар месяца.
- Данные локальны для конкретного браузера и устройства. Синхронизация между телефоном и компьютером не предусмотрена.

## Лицензия

Проект создан для личного учебного использования. Данные студентов обрабатываются локально; при размещении на публичном хостинге помните о правилах обработки персональных данных вашего учебного заведения.
